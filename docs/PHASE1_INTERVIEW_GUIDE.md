# Phase 1 用户访谈提纲

## 目标

验证教师和数学内容创作者是否认可“Prompt → 教学规划确认 → 渲染”的工作流，并收集可直接用于黄金评测集的 Prompt、质量标准与失败边界。

项目发起人决定以 3 个独立 Luna 子 agent 作为 Phase 1 代理用户面板。代理访谈可用于内部需求发现、黄金集构建和开发门禁，但必须标记为 `synthetic_interview`，不得表述为真实用户或市场验证。

## 招募配额

代理面板至少覆盖 6 个 Persona：

- 2 位初高中数学教师
- 1 位大学数学教师
- 1 位数学科普或课程视频创作者
- 1 位教辅/在线教育内容编辑

未来如能接触真实用户，沿用本提纲补充访谈，优先覆盖不同教龄、课程平台和不熟悉 Manim 的用户。

## 访谈流程（45–60 分钟）

### 1. 背景与现有工作流

1. 你主要面向什么学生或观众？教授哪些数学内容？
2. 最近一次制作数学动画或动态课件是什么任务？
3. 从构思到成片通常使用哪些工具、耗时多久？
4. 哪个环节最耗时、最容易返工或最依赖专业技能？

### 2. 真实任务回放

1. 请挑一个近期真实需求，用你平常会说的话描述给动画制作者。
2. 成片必须出现哪些公式、图像、关键点或推导步骤？
3. 哪些数学错误会让这条动画完全不可用？
4. 哪些视觉问题可以接受，哪些必须返工？
5. 你希望动画多长？用于课堂、课程视频还是短视频？

至少为每位受访者收集 3 条原始 Prompt；不要替用户润色后再记录。

### 3. 工作流验证

向用户展示以下概念流程，不承诺尚未实现的功能：

```text
输入自然语言
→ 系统展示教学规划、公式步骤和假设
→ 用户修改或确认
→ 系统生成并渲染动画
→ 用户查看结果、错误和版本
```

提问：

1. 你是否愿意在渲染前确认教学规划？为什么？
2. 规划面板中最需要修改的是公式、顺序、文字、时长还是视觉风格？
3. 生成代码只读可见、但不能在线修改是否影响使用？
4. 低清预览等待多久仍可接受？终渲多久可接受？
5. 第一次结果不正确时，你愿意修正 Prompt、修改规划还是直接放弃？
6. 什么错误解释能帮助你完成下一步？
7. 你是否需要比较或回退到此前版本？

### 4. 质量和价值判断

1. 数学正确、教学有效、画面精致、生成速度四项如何排序？
2. 你会如何判断动画可以用于正式课堂或公开发布？
3. 这项工具每周能替代多少制作时间才值得持续使用？
4. 你是否愿意为稳定生成、版本管理或高清导出付费？

### 5. 收尾核验

1. 将记录的 Prompt 原样读回，请用户确认。
2. 逐条确认受众、教学目标、必须内容、禁止错误和目标时长。
3. 请求允许将匿名化 Prompt 纳入内部评测集。
4. 代理访谈记录为 `synthetic_interview`；未来真实访谈记录为 `real_interview`，且不保存姓名、学校或联系方式。

## 记录模板

- 访谈 ID：`synthetic-AGENT-NN` 或 `real-YYYYMMDD-NN`
- Persona 类型：教师 / 创作者 / 内容编辑
- 受众：K12 / 大学 / 泛知识观众
- 现有流程与耗时
- 核心痛点
- 工作流接受度
- 可接受预览/终渲等待时间
- 首选编辑内容
- 失败容忍度
- 版本与错误解释需求
- 原始 Prompt 及逐条验收要求

## 主持人注意事项

- 代理访谈是当前内部开发依据，但不把它写成真实市场证据。
- 不向用户暗示某个答案更理想。
- 不承诺几何、线代、语音、时间轴或任意 Python 编辑。
- 不收集不必要的个人信息。
- 数学正确性由父 agent 复核，真实用户意见不能替代数学验证。
