# Phase 1 代理用户访谈汇总

## 方法

父 agent 先设计统一访谈提纲，再让 3 个相互独立的 Luna 子 agent 分别扮演代理用户。每个面板覆盖 2 个 Persona，并以自然用户表达提出任务、成片要求、错误边界和工作流偏好。所有输出均按 `synthetic_interview` 保存。

## 代理面板

| 面板 | Persona | 主要任务 | 候选 Prompt |
|---|---|---|---:|
| Bohr | 初高中教师、大学数学教师 | 公式推导 | 18 |
| Mill | 高中教师、数学内容创作者 | 函数可视化 | 18 |
| Confucius | 课程编辑、教育产品内容负责人 | 混合任务与边界案例 | 16 |

共获得 52 条候选任务，父 agent 按首版范围、重复度、可验证性和数学正确性筛选出 30 条黄金 Prompt。

## 共识与差异

- 数学错误容忍度接近零，数学正确性必须拥有一票否决权。
- 用户愿意在渲染前确认 ContentPlan，重点编辑公式、步骤顺序、时长和视觉风格。
- 低清预览期望在数秒到一分钟内出现；精确性能门禁留待渲染基准测试确定。
- 失败信息应区分规划、代码生成、静态校验和渲染阶段，并保留版本轨迹。
- 教师偏好完整解释和课堂可读性，内容创作者更关注节奏、画幅和视觉重点。

## 排除项

几何证明、线性代数、统计图、隐式曲线、语音、用户素材上传和在线编辑任意 Python 不进入首版核心集。一个端点标记容易误导的分段函数样本，以及存在条件表述风险的候选推导被剔除。

## 证据边界

代理用户解决了当前无法招募真实用户时的内部需求发现问题，可作为 Phase 1 开发输入；它不能证明真实用户的采用意愿、付费意愿或实际工作流适配度。未来真实访谈应作为补充验证，而不是改写当前数据来源。
